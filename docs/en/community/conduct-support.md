# Conduct and support

[Nederlands](../../nl/community/conduct-support.md) | **English**

## How do we collaborate well?

Everyone can ask questions, report bugs and discuss ideas. This page explains **expected behavior**, where developers can find help and how to report vulnerabilities privately. Respectful disagreement is welcome; sharing private information is not.

<!-- section: conduct -->
## Conduct

Discuss evidence and ideas respectfully. Harassment, threats, discrimination,
doxing and deliberate humiliation are not accepted. Never publish another
person's private information or confidential project material.

<!-- section: enforcement -->
## Enforcement

Maintainers may edit or remove harmful content and restrict participation. A
final standard Code of Conduct and private contact still require owner approval
before public launch.

<!-- section: support -->
## Support channels

Use Q&A Discussions for development questions, issues for reproducible Developer
Kit bugs and RFC Discussions for contract proposals. There is no production
support promise. Third-party module support remains with its author unless a
separate agreement says otherwise.

<!-- section: security -->
## Security reports

Never report a vulnerability in a public issue. Use GitHub Private Vulnerability
Reporting and include component, impact, reproduction and affected version or
commit. Activation is a `MANUAL GITHUB SETTING REQUIRED` before launch; current
private-repository API checks could not verify it as active.

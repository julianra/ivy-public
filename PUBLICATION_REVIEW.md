# Publication review — owner decisions required

The repository must remain private until every blocking item below is resolved
and the owner gives separate, explicit permission to make it public.

## Blocking legal decisions

- [ ] Confirm the authorised ANWOR copyright holder and copyright notice.
- [ ] Approve or reject Apache-2.0 for Developer Kit files.
- [ ] Decide whether a DCO is sufficient or a CLA is needed.
- [ ] Obtain legal wording for the ANWOR System Module License.
- [ ] Obtain legal wording for the ANWOR Community Module License.
- [ ] Approve trademark and badge-use rules.
- [ ] Review the complete transitive dependency licence inventory.

## Blocking product decisions

- [ ] Approve repository and organisation name for launch.
- [ ] Approve the exact public compatibility promise.
- [ ] Decide whether the manifest-v3 subset is stable enough to expose.
- [ ] Decide which module, if any, becomes the first public reference module.
- [ ] Decide whether public SDK components become canonical in this repository.
- [ ] Approve the distinction between `ANWOR Official` and `ANWOR Verified`.

## Blocking community decisions

- [ ] Select a final standard Code of Conduct and private reporting contact.
- [ ] Name initial maintainers and CODEOWNERS.
- [ ] Approve Discussion categories and issue labels.
- [ ] Decide contribution response expectations.
- [ ] Decide how optional contributor rewards are documented and administered.

## Blocking security and privacy checks

- [ ] Independent secret scan of the exact launch commit.
- [ ] Human review for private Core or module implementation leakage.
- [ ] Human review of screenshots and diagrams.
- [ ] Enable private vulnerability reporting if available.
- [ ] Enable supported secret scanning, dependency alerts and code scanning.
- [ ] Enable branch rules after upgrading the private-repository plan or as part
      of the separately approved public launch; GitHub rejected them while this
      repository remained private.
- [ ] Re-run clean-clone builds without private repository access.

## Launch approval

- [ ] Repository owner explicitly authorises changing visibility from PRIVATE to
      PUBLIC in a separate instruction.

Until the last item is checked, no public release, announcement, package publish
or visibility change is authorised.
